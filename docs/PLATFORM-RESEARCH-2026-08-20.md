## 1. 지도 공급자 — 결론: MapLibre + OpenFreeMap이 유일하게 4조건 전부 만족

전제 4조건: 정적 사이트(GitHub Pages, 서버 없음) · 무료 지속 · 양피지 커스텀 스타일 · GPS 경로 오버레이.

| 공급자 | 무료 한도 | 키/과금 리스크 | 커스텀 스타일 | 판정 |
|---|---|---|---|---|
| **OpenFreeMap** (벡터, MapLibre 필요) | **무제한 · 상업 허용** | **키 자체가 없음** | 스타일 JSON 완전 자유 — 양피지 팔레트를 직접 소유 | **1순위** |
| Stadia Maps | 월 200k 크레딧(타일당 1) | 도메인 인증(키 불필요), 초과 시 429 정지 — 과금 폭탄 없음 | Stamen Watercolor 등 종이 감성 기본 제공 | 2순위 — 단 **비상업 전용**, 수익화 시 $20/월 |
| MapTiler | 월 5,000 세션 | 키 + 도메인 제한 | 가능, 로고 강제 | 폴백용 |
| Google Maps | 2025-03 개편: Dynamic Maps 월 10,000 로드 | **Cloud 결제 계정 필수**, referrer 뚫리면 과금 | Map ID 클라우드 스타일링(추가 과금 없음) | 탈락 — "무료 지속" 전제와 불일치 |
| Mapbox GL JS | 월 50,000 로드 | URL 제한이 공식 "best-effort" — 도용 = 과금 | 업계 최고 | 탈락 — 같은 이유 |
| Protomaps/PMTiles 자가호스팅 | 무료 | — | 자유 | 탈락 — 플래닛 ~120GB, GitHub Pages(1GB) 불가 + range request 버그. 러닝 앱은 전 세계 커버 필요 |
| OSM 공식 raster (현재 사용 중) | 무료 | 키 없음 | raster라 불가 | **정책 리스크** — usage policy가 "heavy use 앱 배포는 사전 허가 없이 금지 · 예고 없이 차단 가능"을 명시 |

### 기존 코드 결정과의 충돌 — 정직하게

`RouteMap.tsx:7-17`은 MapLibre를 "18.9MB라 과하다"로 기각하고 Leaflet(전이 의존성 0)을 택했다.
18.9MB는 npm 패키지 크기고, 실제 비용은 **동적 청크 ~210KB gz** — 그래도 앱 전체(gz 137KB)의
1.5배다. 이 긴장은 실재한다. 정리:

- **지금(검증 전, 사용자 적음)**: 현행 유지 가능. OSM 정책은 저사용을 막지 않는다.
  attribution 유지(이미 함) + 타일 캐싱 금지 준수.
- **배포 확산 직전이 결정 시점**: (A) 미학·독립성 우선 → MapLibre + OpenFreeMap
  (+타일 URL만 MapTiler로 바꾸는 폴백 — OpenMapTiles 스키마 호환). 양피지 스타일을
  픽셀 단위로 소유, 지도가 보드와 같은 종이가 된다. 비용: 지도 화면 한정 +210KB(1회, PWA 캐시).
  (B) 무게 우선 → Leaflet 유지 + Stadia 도메인 인증. 비용: 비상업 조건, 스타일은 남의 것.
- OpenFreeMap 리스크: 1인 운영·기부 재정·무SLA. 폴백 이중화로 상쇄 가능.

## 2. Strava · Nike Run Club

### 2-1. 연동 판단 (핵심만)

- **Strava API**: 2024-11 약관 — 데이터는 본인에게만 표시(우리 use case는 통과), AI 학습 금지, 룩앤필 복제 금지.
  **2026-06 개편 — 사실상 유료화**: Standard 티어 = 개발자 본인이 Strava 구독($11.99/월) 필수 + **연결 10명 제한**.
  그 이상은 Extended Access 심사. 게다가 OAuth가 PKCE 미지원(client_secret 필수) → 정적 사이트 단독 불가,
  토큰 프록시(Cloudflare Worker 등) 필요.
- **NRC**: 공개 API 없음. 비공식 API는 2024-03 Nike가 서드파티(RunGap) 차단 — 제품 기능으로 부적격.

**현실적 경로**: ① 지금 — 자체 GPS가 정본(이미 그렇다) + **GPX 내보내기**(사용자가 스스로 Strava에 올림 — API·비용 무관)
② 다음 — Strava에서 내보낸 GPX **가져오기**(역시 API 불필요) ③ 나중 — 검증 통과 후 Extended Access + 프록시.

## 3. "보스전" → 시련(試鍊) 구간 설계안

### 금지선 매핑 (D3 · §4.3 · pace.ts)

| 금지 | 이 설계의 준수 |
|---|---|
| "보스" 어휘 | **시련** — 성경 속 실제 대결·시험 사건만 (풍랑·광야·홍해) |
| 십자가=보스전 | 수난·lament 자리는 시련 지정 **금지** — check-content가 기계로 검사 |
| 예수 능력의 스킬화 | 상대는 예수/하나님이 아니라 바다·광야·거리. 동사는 "이긴다"가 아니라 **"건넌다·지난다"** |
| 공로 차등(축척 모드를 안 둔 이유) | 시련을 넘어도 인장은 **같은 인장** — 보상은 늘 말씀. 다른 것은 경험이지 보상이 아니다 |
| 죄책감 없는 복귀(D9) | 실패·리셋 없음 — 여러 러닝에 나눠 건너도 된다. 시련은 관문이 아니라 이름 붙은 구간 |

### 메커니즘 — "게임의 뼈": 이름 붙은, 두렵고, 기억에 남는 구간

보스전이 게임에서 하는 일 = 긴장의 축적 → 정점 → 해소. 이걸 **구간**으로 번역한다:

1. **시련 구간 = 여정에서 가장 긴 걸음.** pace.ts 상한(실제 12km)쪽으로 고른 구간에 이름을 붙인다
   — "유라굴로의 풍랑"(바울), "광야 사십 일"(예수), "홍해"(출애굽). 어려움 자체가 정직하다: 진짜 멀다.
2. **연출의 정점.** 구간에 들어서면 — 보드 창의 패널이 폭풍(paul-3 lightning 이미 있음)·러닝 화면
   등불 구절이 그 사건의 본문("어찌하여 무서워하느냐")·햅틱 패턴 변화. 건너는 중엔
   "아직 바다 위입니다"가 다음 자리 게이지의 문장이 된다.
3. **해소 = 도착 자리의 mood가 맡는다.** 풍랑 뒤 잔잔한 바다(wonder) — 기존 Celebration이
   그대로 정점 해소. 새 보상 시스템 불필요.

### 구현 스케치 (moods.ts 패턴 그대로 — 편집 판단은 별도 파일)

- `src/data/trials.ts` — `{ 'paul:ep-XX': { name: '유라굴로의 풍랑', kind: 'storm' } }` 편집 지정
- `pace.ts` — trial 구간은 clamp 상한으로(또는 이미 긴 구간을 골라 지정만)
- `Run.tsx` / `Ambient.tsx` / `QuestBoard.tsx` — 구간 진입 연출(구절·햅틱·패널 공기)
- `Reveal.tsx` — 건넌 러닝의 서사 한 줄
- `check-content.mjs` — trial id 실존 + **lament 자리와 교집합 ∅** 기계 가드

후보 자리(콘텐츠 확인 필요): 바울 유라굴로 폭풍 구간(paul-3 패널에 lightning 좌표 존재),
출애굽 홍해, 예수 광야 시험. 각 여정 1개면 충분 — 많으면 시련이 아니라 소음.
