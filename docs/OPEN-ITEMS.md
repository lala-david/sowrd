## P0 — 신학 제약 위반이 남아 있다

### 에피소드 아트에 후광·과대 인물이 일부 남음
- **어디**: `src/assets/art/episodes/*.webp` (68장)
- **무엇**: PCK 제약은 "그리스도를 인물로 직접 묘사하지 않는다. 후광 금지. 사람은 원경의
  얼굴 없는 실루엣으로만"이다. 생성 모델이 구도를 완성하려고 홀로 선 인물을 습관적으로 넣고,
  그 인물을 성인으로 해석해 머리 뒤에 밝은 원반을 그린다.
- **시도한 것**:
  1. `"at most one tenth of the picture height"`로 크기 지정 → 무시됨(실측 16~43%)
  2. `"no halo"` 부정 지시 → 오히려 그려짐(부정 목록이 그 사물을 불러온다)
  3. 머리 주변을 긍정형으로 채움(`"only open empty sky above the head"`) → 일부 개선
  4. 스캐폴드를 **"사람 없는 장소"**로 전환 → 여전히 인물이 들어감
- **현재 상태**: `node scripts/audit-art.mjs src/assets/art/episodes` 로 검출 가능.
  "사람 없는 장소" 스캐폴드로 전체 재생성한 뒤 **35/68 플래그**(그 전 49장에서 줄었다).
  단 **검출기에 알려진 오탐**이 있다 — 인물과 그 아래 어두운 사물(탁자·그림자)이 하나의
  연결 성분으로 합쳐져 키가 부풀려진다(peter-ep10이 그 예로, 실제 인물은 작다).
  실제 위반 장수는 35보다 적다. 눈으로 확정한 위반은 `exodus-marah`(후광, 재생성으로 해소)와
  `peter-ep07`·`peter-ep11`(과대 인물)이었다.
- **다음 수순**:
  - 검출기의 연결 성분 분리 개선(세로 중앙 기준 폭 프로파일로 인물/사물 분리)
  - 확정된 위반 장만 `--force`로 재생성하거나, `mcp__recraft__erase_region`으로 후광만 제거
  - 최후 수단: 해당 자리는 인물이 없는 다른 사건 요소로 주제문 교체

## P1 — 측정·데이터

### GPS 필터 실기 검증이 없다
- **어디**: `src/lib/geo.ts` `watchDistance()`
- 등속 칼만 필터로 교체했고 **합성 궤적 시뮬레이션**에서 전 조건 오차 −0.1~−0.5%를 확인했다
  (예전 게이트는 빌딩사이 10'00"/km에서 −65.8%).
- 다만 검증이 전부 합성 데이터다. **실제 기기에서 실제로 달린 GPS 로그로 확인한 적이 없다.**
  실기에서 확인할 것: 터널·지하도 진입 시 속도 추정의 관성, 신호등 정지 후 재출발 반응,
  `ACCEL_NOISE_MS2 = 0.5`가 실제 러너에게 맞는 값인지.

### 존(zone) 기준선이 "오늘 평균"이다
- **어디**: `src/lib/runAnalysis.ts` `zoneOf` / `bandOf`
- 존 경계가 "자기 평균 대비 상대값"이라면서 정작 기준이 **그날 런의 평균**이다.
  오늘 전체가 느렸으면 전 구간이 "평소대로"로 찍힌다. 최근 5~10회 평균이 진짜 기준이어야 한다.

### 죽은 통계 코드
- **어디**: `src/lib/runAnalysis.ts`
- `ZONES` / `zoneOf` / `zoneSeconds` / `slowestKm` / `splits[].deltaSec` 가 계산만 되고
  **어느 화면에도 렌더되지 않는다**. `--color-zone-1..5` 토큰도 마찬가지.
  삭제하거나 렌더할 것. 특히 5계급 존은 색약 검사에서 실패한다(deutan 최악쌍 ΔE 8.0,
  z1 대비 2.02:1) — 지금은 무해하지만 쓰는 순간 접근성 위반이다.

### 이동창(`WINDOW_KM = 0.2`)이 사실상 죽어 있다
- **어디**: `src/state/run.ts` `tick()`
- 200m를 45초 안에 지나려면 3'45"/km보다 빨라야 한다. 그보다 느린 **모든 사용자에게
  창은 항상 45초**이고, 느릴수록 창이 덮는 거리가 짧아진다(10'00"/km에서 75m).
  잡음이 가장 큰 사람에게 표본을 가장 적게 주는 구조다. 창 조건을 `&&`로 바꾸고 상한을 둘 것.
- 표시 해상도도 문제다. `fmtPace`가 초 단위까지 찍는데 실제 불확실성은 ±20~35초다.
  5초 단위 반올림이나 밴드 표시(`5'45"~6'05"`)가 정직하다.

## P2 — 접근성

- **작은 글자가 여전히 많다**: 12px 미만 65곳(10px 10곳 포함). 「글자 크기」 설정(zoom 1.15/1.3)을
  넣어 레버는 생겼지만 기본값 자체는 그대로다. 본문 타이포를 rem으로 옮기는 것이 근본 해결.
- **`<main>` 랜드마크가 홈에만 있다**. 나머지 화면과 스킵 링크가 없다.
- **Save-Data 미대응**: `navigator.connection` / `prefers-reduced-data` 를 읽는 코드가 0건.
  프리캐시를 1.7MB로 줄였지만 데이터 절약 모드 사용자에게 별도 처리는 없다.
- **reduced-motion이 페이드를 하드컷으로 만든다**: `index.css`의 `transition: none !important`가
  호흡 기도 교차 페이드(4.5초)와 도달 토스트를 뚝 끊기게 한다. 가드가 상황을 악화시키는 경우.
- **Collection 자리 버튼의 접근 이름에 도달 여부가 없다**: 시각적으로는 인장으로 구분되지만
  스크린리더는 어디를 다녀왔는지 모른다.

## P2 — 코드·구조

- **`streakDays`가 남아 있다**: 화면에서는 "이번 주 N일"로 교체했지만 스토어 필드와
  `commitRun`의 grace-day 로직은 그대로다. 쓰지 않는 상태를 유지 중.
- **`totalKm`와 `lifetime.km`이 두 진실**: 정상 경로에서는 일치하지만, v3 마이그레이션을 거친
  기존 사용자는 영구 격차가 생긴다(runs[]가 100건에서 잘려 있었으므로).
  `lifetime.km = max(lifetime.km, Σ progress.cumulativeKm)` 로 보정하는 v5가 필요.
- **`clearFlash`가 정의만 있고 호출부가 없다** (`src/state/run.ts`).
- **`prayer.ts`가 여전히 미사용**: `Intercession` 타입과 `validateAlias`를 만들어 뒀지만
  어느 화면도 쓰지 않는다. `Profile`의 이름 입력은 `validateAlias`를 우회한다.
- **`mode` / `goalKm` / `goalSec`을 Run이 읽지 않는다**: 「목표 거리」「목표 시간」을 골라도
  러닝 화면이 그 값을 쓰지 않는다.
- **`Courses` 화면이 미구현 콘텐츠를 안고 있다**: 화면 스스로 "실제 GPS 주행 연동은 아직입니다"라고
  밝힌다. 탭에서는 뺐지만 화면은 남아 있다.
- **`RouteMap`이 점 쌍마다 폴리라인을 만든다**: `compactTrace(cap=400)`가 상한을 걸어 실사용상
  문제는 없지만, 같은 밴드끼리 이어붙이면 3~10개로 줄어든다.
- **`RouteMap`의 CSS 변수 해석을 iOS Safari에서 확인하지 못했다**: `cssVar()`로 미리 풀어서
  넘기도록 방어했지만 실기 확인은 없다.

## 이번 작업에서 확인된 사실 (재발 방지용)

- **부정 목록은 그 사물을 불러온다.** `"no border"` → 테두리가 그려졌고, `"no halo"` → 후광이
  그려졌다. 무엇을 그리지 말지가 아니라 **그 자리에 무엇을 그릴지**를 지정해야 한다.
- **프롬프트에 숫자·비율을 쓰면 글자로 그려진다.** 예전에 "45%"가 그림 안에 텍스트로 나왔다.
- **recraft v3는 프롬프트 상한 1000자**라 이 스캐폴드가 들어가지 않는다. v4.1을 쓰되
  비율 크기(`1:1`)만 받고 `style` 파라미터를 거부한다.
- **`accuracy`는 "어디에 있는가"의 오차지 "얼마나 움직였는가"의 오차가 아니다.** 이것을
  변위 문턱으로 쓴 것이 GPS 거리 오차 −66%의 뿌리였다.
- **위치만 평활하면 거리가 깎인다.** 랜덤워크 칼만으로 위치를 평활한 뒤 차분으로 거리를 재면
  저주파 통과 때문에 느린 이동이 사라진다(개방하늘 10'00"/km에서 −95.7%).
  속도를 상태에 넣고 |v|·dt로 적분해야 한다.
- **Windows에서 sharp가 파일 핸들을 쥔 채 같은 경로에 쓰면 `EBUSY`**가 난다.
  원본을 `fs.readFileSync`로 먼저 메모리에 올릴 것.
- **백그라운드 생성이 끝났는지는 완료 알림으로만 판단할 것.** 로그 파일 꼬리를 보고
  완료로 오판해서, 68장 생성이 아직 도는 중에 최적화·커밋을 돌렸다. 그 결과 커밋에
  재생성본과 이전본이 섞였고 31장이 미최적화(35MB)로 들어갔다. 다음 커밋에서 바로잡았지만,
  긴 배치 작업 뒤에 후처리를 붙일 때는 반드시 완료를 확인하고 시작해야 한다.
