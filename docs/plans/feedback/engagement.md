# 몰입·리텐션 시스템 (engagement) — 1차 검증 피드백 전문

## 김정훈 목사(신학) — 7/10
한줄평: 다크패턴을 배제한 윤리적 뼈대와 CI 감수 게이트는 교단 감수 기준에 근접했으나, 부활의 기쁨까지 'quiet'로 봉인한 ep12 설계와 성구 1.5초 노출을 '감동'으로 계량하는 정의, 감수 기본값이 꺼져 있는 마이크로 보상 스키마는 이대로 내보낼 수 없다.

### 이슈
- [high] ep12의 mood를 'quiet' 고정으로 명시(③ PeakEndSchema 주석, ⑤)했으나 GDD 12장은 '수난→부활'로서 빈 무덤·엠마오·'기쁨의 피날레'까지 포함한다. 수난의 절제는 옳지만 부활의 승리까지 침묵시키는 것은 정통 개혁주의 부활 신앙에 어긋난다. 십자가 없는 부활도 오류지만, 기쁨 없는 부활도 오류다. 고린도전서 15장이 말하는 부활은 '사망아 너의 승리가 어디 있느냐'의 승전가다. 장당 PeakEnd 1건 구조가 수난과 부활이라는 상반된 두 정점을 하나의 무드로 뭉개고 있다.
  - 제안: ep12를 수난 비트(quiet)와 부활 비트(triumphant 또는 warm)의 두 PeakEnd로 분리하라. 스키마를 에피소드당 복수 비트 허용으로 확장하고, '수난=quiet 필수'는 Zod refine으로 강제하되 부활 비트는 기쁨을 허용하라.
- [high] MicroRewardSchema의 needsReview 기본값이 false다(③). '베드로가 배에서 일어섰다' 같은 이야기 조각은 그 자체가 성경 내레이션의 의역이며, T3에서 스스로 인정했듯 짧은 문장일수록 자의적 해석 리스크가 크다. 그런데 감수 대상 여부를 데이터 작성자의 자기 판단(true로 켜는 것)에 맡기면, CI 게이트(⑩)는 체가 아니라 구멍 뚫린 그물이다. 감수위원 경험상 문제는 항상 '감수 필요 없다고 판단된' 문장에서 터진다.
  - 제안: needsReview 기본값을 true로 뒤집고, false는 감수자가 명시적으로 해제하는 opt-out 구조로 하라. 스키마에 reviewedBy·reviewedAt·contentVersion 필드를 추가해 문구 수정 시 감수가 자동 무효화되게 하라.
- [high] '감동 순간 도달'을 '성구가 화면에 1.5초 이상 노출'로 조작적 정의(⑤)한 것은 신학적으로 위험한 환원이다. 말씀 노출 시간을 은혜 체험의 대리 지표로 삼는 순간, 하나님의 말씀이 KPI의 소재가 된다. 더구나 이 수치가 '나의 여정 데이터'로 사용자에게 노출된다(⑥ 셀렉터, v1 로드맵). 성도가 자기 '감동 도달률 73%'를 보는 장면을 상상해 보라. T7에서 '감수 권장'으로 격하해 둔 것은 안이하다.
  - 제안: 내부 지표명을 '엔딩 열람률' 등 가치중립 용어로 바꾸고, 사용자 노출 화면에서는 감동·은혜류 계량 표현을 금지 목록에 넣어라. T7을 '감수 필요'로 격상하라.
- [medium] 자이가르닉 훅(nextHook, 실루엣 미리보기)이 ep12에서 나가는 훅만 금지했을 뿐, ep11→ep12로 들어가는 훅에는 규칙이 없다. '다음 이야기가 기다려요' 문법으로 십자가 수난을 궁금증 유발 소재(클리프행어)로 쓰는 것은 수난 절제 원칙의 정면 위반이다. 겟세마네 다음 장을 '다음 화 예고'처럼 팔 수는 없다.
  - 제안: ep11의 nextHook·실루엣 미리보기에도 quiet 규정을 적용하라. 수난으로 진입하는 훅은 호기심 문법이 아니라 '함께 있어 달라'(마 26:38)는 초대의 문법으로 별도 감수하라.
- [medium] 피크-엔드 화면에서 창작 한 줄(line)과 성경 본문(verseRef)이 병치 표시되는데, 창작 문장과 성경 말씀의 시각적 구분 규칙이 ⑦ UI 토큰 표에 전혀 없다. 세리프·양피지 톤을 공유하면 사용자가 창작 내레이션을 성경 본문으로 오인한다. 이것이 바로 이단들이 즐겨 쓰는 '본문과 해석의 경계 흐리기'와 같은 효과를 의도치 않게 낸다.
  - 제안: 성경 본문은 인용부호+출처 병기 필수, 창작 문장은 출처 표기 없는 별도 스타일로 명확히 구분하는 UI 규칙을 ⑦에 추가하고 I 계열 통합 테스트로 검증하라.
- [medium] T2(성경 번역본·저작권)를 '감수+법무 필요'로 표기만 하고 M1~v1 어느 마일스톤에도 배정하지 않았다. 개역개정은 대한성서공회 저작권 하에 있어 상업·앱 사용 시 허락 절차가 필요하고, 수직 슬라이스는 이미 마태복음 14:31을 화면에 박아 놓았다. M4에서 12장 전체 peakEnds 데이터를 만든 뒤 번역본이 바뀌면 전량 재작업에 재감수다.
  - 제안: 번역본 확정과 사용 허락(또는 새번역·공동번역 등 대안 검토)을 M4 착수 조건으로 로드맵 ⑧에 명시하라.
- [medium] 복귀·알림 문구(T5)가 '감수 권장'에 그치고, 톤 검증 수단이 '코드 리뷰 체크리스트'뿐이다(⑥). 알림 문구는 이 제품에서 가장 공적으로 노출되는 텍스트인데, 개발자 코드 리뷰가 '은혜·축복의 마케팅 문구화'를 걸러낼 신학적 안목을 가졌다고 볼 근거가 없다.
  - 제안: T5를 '감수 필요'로 격상하고, welcome.ts의 문구를 microRewards와 동일하게 needsReview 스키마 대상 데이터로 승격하라.
- [low] '통찰(insight)' 명칭의 영지주의적 뉘앙스는 스스로 지적(T6)했으나 '감수 권장'으로 미뤘다. 게임 숙련('흔들림 없이 완주')을 영적 깨달음의 어휘로 보상하는 구조는 '믿음 좋으면 게임 잘한다'는 역방향 오해의 소지도 있다.
  - 제안: T6이 제안한 '묵상' 또는 '깨달음의 한 걸음'으로 v1 데이터 작성 전에 확정하라. 명칭은 나중에 바꾸면 배지·대사 전체 재감수 비용이 든다.
- [low] 90초 무보상 시 자동 발동하는 안전판 보상(⑤)은 장당 1회 상한이 있어도 '침묵의 구간'을 시스템이 못 견디는 설계다. 겟세마네·수난 같은 장에서는 90초의 여백 자체가 콘텐츠다.
  - 제안: 안전판을 verb·mood별로 비활성화 가능하게 하고, quiet 무드 장에서는 기본 off로 하라.

### 필수 수정
- ep12 피크-엔드를 수난(quiet)과 부활(기쁨) 두 비트로 분리 — 부활의 승리를 침묵시키는 현행 'quiet 고정'은 교리적 결함이다
- MicroRewardSchema의 needsReview 기본값을 true로 변경하고 감수자 서명 필드(reviewedBy·reviewedAt·contentVersion)를 스키마에 추가
- 성경 번역본 확정 및 저작권 허락 절차를 M4(피크-엔드 데이터화) 착수 조건으로 로드맵에 명시
- '감동 순간 도달률' 명칭·정의 재검토 — 사용자 노출 화면에서 은혜·감동의 계량 표현 금지
- 창작 문장과 성경 본문의 시각적 구분 규칙(인용부호·출처 병기)을 UI 토큰 표와 통합 테스트에 추가
- ep11→ep12 진입 훅에 수난 클리프행어 금지 규칙 적용

## 유나(게임 디자인) — 6/10
한줄평: 배관 설계는 프로급인데 수도가 끊겨 있다 — 재방문할 콘텐츠와 트리거가 전부 '비범위'라 D1부터 루프가 마르고, 유일한 플레이어블(ep08)에서는 자기 완화책(R2 홀드 큐)이 자기 합격 기준(M2 실시간 리듬)을 정면으로 부정한다.

### 이슈
- [high] 내부 모순: M2 합격 기준은 'ep08 1회 플레이에서 마이크로 보상 2~3회, 90초 무보상 구간 없음'인데, R2 완화책은 '균형/리듬 동사 플레이 중 토스트를 홀드 큐에 넣고 결과 화면 직전 방출'이다. ep08은 균형 동사다. 즉 유일한 플레이어블 에피소드에서 실시간 토스트는 정책상 0개가 되고, S1의 '~45초 첫 마이크로 보상' 시나리오도 성립하지 않는다. M2 기준은 검증 불가능하거나 R2는 사문화된다.
  - 제안: ep08의 물결 사이클을 활용하라. calm 구간(파도 사이 4.2~7.4초)은 홀드 중이어도 인지 부하가 낮으므로 calm 진입 순간에만 토스트 방출을 허용하는 '윈도 방출' 정책으로 R2를 재정의하면 실시간 리듬과 플로우 보호가 양립한다. M2 기준도 '플레이 중 calm 윈도 방출 2~3회'로 고쳐라.
- [high] D1~7 루프가 스코프 안에서 끊긴다. 초대형 알림(Capacitor 이후), 데일리 묵상 콘텐츠, 허브 대화 전부 비범위인데 플레이어블은 ep08 하나(약 3분)다. S2 시나리오의 '허브 대화 1개 = 작은 완결'은 존재하지 않는 콘텐츠를 전제한 픽션이다. Hook 모델의 외부 트리거 0개 + 재진입해도 할 게 없는 상태에서 '3초 이어하기'는 텅 빈 맵으로 3초 만에 데려다주는 시스템일 뿐이다. 리텐션 시스템 플랜이 리텐션의 진짜 병목(재방문 사유)을 전부 타 플랜에 떠넘겼다.
  - 제안: v0.5 게이트에 최소 재방문 사유 1개를 스코프로 편입하라. 후보: (a) ep08 통찰 목표 2~3종을 M2와 동시 출시(재도전 사유), (b) 베드로 허브 대사 드립피드 최소 5줄(bus 계약 'hub/dialogue'의 첫 소비자), (c) PWA 로컬 알림 초대형 1종. 이 중 하나도 없으면 M3·M5는 측정할 대상 자체가 없다.
- [high] 마이크로 보상이 계정 영구 1회 소진(claimedMicroRewards 영속)이라 재플레이 세션에는 30~90초 리듬이 통째로 없다. 콘텐츠가 부족한 초기일수록 핵심 활동은 재플레이인데, 그 재플레이가 가장 보상이 마른 경험이 된다. S4(숙련 유저 재도전)조차 통찰 배지(유한) 외에는 무보상이고, 안전판도 '장당 1회'라 두 번째 재도전부터는 완전 침묵이다. '한 번 본 유저에게는 리듬이 죽는 시스템'을 보상 리듬 시스템이라 부를 수 없다.
  - 제안: MicroRewardKind별로 소진 정책을 분리하라: story-fragment는 계정 1회(스포일러성), companion-line은 풀에서 세션당 1~2개 로테이션(재플레이 반응 대사 — Hades 드립피드의 본체가 바로 이것), card-progress·insight 근접 알림은 상태 변화 시마다. 스키마에 claimPolicy: 'once' | 'perSession' | 'onChange' 필드 추가.
- [medium] 북극성 지표 '감동 순간 도달률'이 자동 달성되는 허영 지표다. RewardScreen은 completeEpisode 시 무조건 렌더되고 성구가 항상 표시되므로 '1.5초 노출' 기준이면 즉시 이탈 유저를 빼고 사실상 100%에 수렴한다. peakend.viewed / episode.complete는 아무것도 분별하지 못하고, 분모인 completionRate도 episode.retry가 enter를 재발행하면 재도전하는 몰입 유저가 지표를 끌어내리는 역설이 생긴다.
  - 제안: 도달률 대신 체류를 재라: 피크-엔드 화면 체류 시간 분포(즉시 스킵 vs 3초+ 머묾)와 '사람들 보기' 선택률이 실제 감정 반응의 프록시다. completionRate 분모는 enter가 아니라 고유 에피소드 최초 진입(first-enter)으로 정의하고 retry는 별도 재도전율로 분리하라.
- [medium] 세션 판정이 과발화에 무방비다. visibilitychange(hidden)는 카톡 알림 확인 10초에도 발화한다. 모바일에서 탭 전환은 세션당 수 회가 기본인데 그때마다 endSession→beginSession이면 medianSessionMinutes(목표 3~7분 검증의 근거)와 세션 수가 전부 쓰레기 데이터가 된다. R8은 미발화(iOS PWA)만 다루고 과발화는 다루지 않는다. 지표 모듈의 신뢰성이 M1에서부터 무너진다.
  - 제안: grace window를 도입하라: hidden 후 N분(권장 3~5분) 내 복귀면 동일 세션 연장, 초과 시에만 endedAt을 hidden 시점으로 소급 봉합. U 테스트에 'hidden 30초 후 복귀 → 세션 1건' 케이스 추가.
- [medium] 자이가르닉 훅이 벽으로 이어진다. S1의 '다음 장 실루엣 미리보기'와 peakEnds의 nextHook이 가리키는 ep09~는 전부 playable:false다. 호기심을 열어놓고 탭하면 잠김 — 미완결 긴장은 해소 경로가 있을 때만 리텐션이고, 없으면 '이 게임 아직 안 만들어졌네'라는 이탈 확정 신호다. 가챠 게임에서도 출시 안 된 배너를 미리 보여주는 건 예약 페이지에서나 한다.
  - 제안: nextHook 노출을 다음 장 playable 여부에 조건부로 걸어라(스키마에 이미 optional이니 데이터 규칙으로: 미출시 장은 nextHook 생략). 대신 출시된 콘텐츠 안의 미완결(통찰 미달성, 카드 뒷면 미해금)로 긴장을 돌려라.

### 필수 수정

## 박도윤(엔지니어링) — 6.5/10
한줄평: 코드 현실을 잘 읽은 성실한 플랜이지만, 자기 리스크 항목(R2)과 핵심 시나리오(S1)가 정면 충돌하고, "App 셸 어댑터" 아키텍처는 현재 화면들이 store를 직접 호출하는 구조와 모순되며, 1인 개발 수직 슬라이스 규모 대비 과설계 냄새가 뚜렷하다.

### 이슈
- [high] 플랜 내부 모순: S1 시나리오는 'ep08 플레이 중 ~45초에 첫 토스트'를 약속하는데, ep08은 '균형' 동사이고 R2 완화책은 '균형/리듬 동사 플레이 중 토스트는 홀드 큐에 넣고 결과 화면 직전 방출'이라고 못박았다. 둘 다 참일 수 없다. 실제 WaterWalkGame은 길게 누르기+파도 타이밍 게임이라 플레이 중 토스트는 조작 방해가 맞고, 그러면 M2 완료 기준('플레이 중 마이크로 보상 2~3회, 90초 무보상 구간 없음')과 30~90초 리듬 전제 자체가 무너진다.

App.tsx는 screen 값만 구독할 뿐 액션 호출 지점을 모른다. 어댑터를 App 셸에 두려면 (a) 전 화면을 어댑터 함수 경유로 리팩터링(=플랜이 말한 '최소 수정' 위반)하거나 (b) zustand subscribe로 상태 diff를 감시해 이벤트를 역추론(취약, 재시도/중복 구분 불가)해야 한다. 플랜은 이 비용을 어디에도 계상하지 않았다.

- 마이크로 보상에 텍스트 이외의 실물(스크랩북에 축적되는 시각적 수집 요소)을 최소 1종 추가 — 자막을 보상이라고 부르지 말 것
- D8+ 재방문 이유를 플랜 범위 안에 실물로 하나 이상 포함(허브 드립피드 대사 실제 콘텐츠 등) — 현재 플랜은 복귀 '환대'만 있고 복귀 '동기'가 없다
- 플레이테스트에 비신자·교회 무관 유저 절반 이상 필수 조건 추가, '설교 같다' 게이트를 비신자 기준 0건으로 강화
- '감동 순간 도달률' 지표를 노출 기반에서 자발적 행동 기반으로 재정의(또는 정직하게 개명)
